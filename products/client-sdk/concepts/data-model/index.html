Data Model¶

Understanding runs, threads, messages, and participants in the Client SDK.

Overview¶

The Client SDK abstracts the Agent Protocol data model into intuitive concepts. While you can work with these primitives directly via the REST API, the SDK handles most of the complexity automatically.

Protocol Reference

For the complete protocol specification, see Protocol Data Model.

Core Primitives¶

Threads¶

A thread represents a persistent conversation context between a user and one or more agents.

# Create a persistent conversation
conversation = client.create_conversation()

# Send multiple messages in the same context
response1 = await conversation.send("What's the capital of France?")
response2 = await conversation.send("What's its population?")  # Agent remembers previous context

# Save thread ID to resume later
thread_id = conversation.thread_id

# Create a persistent conversation
conversation = client.create_conversation()

# Send multiple messages in the same context
response1 = await conversation.send("What's the capital of France?")
response2 = await conversation.send("What's its population?")  # Agent remembers previous context

# Save thread ID to resume later
thread_id = conversation.thread_id

Key Properties:

  • thread_id - Unique identifier for the conversation
  • metadata - Custom key-value pairs for filtering/organization
  • participants - List of users and agents in the thread
  • created_at - Timestamp of thread creation

Lifecycle:

  1. Created - Thread is initialized (explicitly or implicitly)
  2. Active - Messages can be sent and received
  3. Archived - Thread is no longer active but preserved
  4. Deleted - Thread and all messages are removed

Runs¶

A run represents a single execution of an agent within a thread.

# Simple completion (ephemeral run)
response = await client.complete_chat("Hello!")

# The SDK automatically:
# 1. Creates an ephemeral thread
# 2. Starts a run
# 3. Waits for completion
# 4. Returns the final response

# Simple completion (ephemeral run)
response = await client.complete_chat("Hello!")

# The SDK automatically:
# 1. Creates an ephemeral thread
# 2. Starts a run
# 3. Waits for completion
# 4. Returns the final response

Key Properties:

  • run_id - Unique identifier for this execution
  • thread_id - The thread this run belongs to
  • agent_id - Which agent is executing
  • status - Current run state (queued, in_progress, completed, failed, etc.)
  • started_at / completed_at - Execution timestamps

Run Statuses:

Status Description
queued Run is waiting to start
in_progress Agent is actively processing
requires_action Waiting for tool execution or user input
completed Successfully finished
failed Execution failed with an error
cancelled User cancelled the run
timeout Run exceeded time limit

Messages¶

A message represents a single communication in a thread.

// Messages are created automatically when you send
const response = await conversation.send("Tell me a joke");

// You can also access the full message object
const messages = await client.getThreadMessages(threadId);
messages.forEach(msg => {
    console.log(`${msg.role}: ${msg.content}`);
});

// Messages are created automatically when you send
const response = await conversation.send("Tell me a joke");

// You can also access the full message object
const messages = await client.getThreadMessages(threadId);
messages.forEach(msg => {
    console.log(`${msg.role}: ${msg.content}`);
});

Message Structure:

{
  "id": "msg_abc123",
  "thread_id": "thread_xyz789",
  "role": "user",  // or "agent", "system", "tool"
  "content": [
    {
      "type": "text",
      "text": "Hello, world!"
    }
  ],
  "created_at": "2025-01-15T10:30:00Z"
}

{
  "id": "msg_abc123",
  "thread_id": "thread_xyz789",
  "role": "user",  // or "agent", "system", "tool"
  "content": [
    {
      "type": "text",
      "text": "Hello, world!"
    }
  ],
  "created_at": "2025-01-15T10:30:00Z"
}

Message Roles:

  • user - Messages from the end user
  • agent - Messages generated by the agent
  • system - System prompts and instructions
  • tool - Tool/function call results

Content Types:

Messages can contain multiple content blocks:

  • text - Plain text content
  • image - Images (URL or data URI)
  • audio - Audio files
  • video - Video files
  • file - Documents, PDFs, etc.
  • function_call - Tool invocation
  • function_result - Tool execution result

See Multimodal Guide for examples.

Participants¶

Participants represent users and agents in a thread.

var thread = await client.CreateThreadAsync();
var participants = thread.Participants;

foreach (var participant in participants)
{
    Console.WriteLine($"{participant.Role}: {participant.Name}");
}

var thread = await client.CreateThreadAsync();
var participants = thread.Participants;

foreach (var participant in participants)
{
    Console.WriteLine($"{participant.Role}: {participant.Name}");
}

Participant Properties:

  • id - Unique identifier
  • role - "user" or "agent"
  • name - Display name
  • metadata - Custom properties

Working with the Data Model¶

Ephemeral vs Persistent Threads¶

Ephemeral Threads (default for simple completions):

# No thread ID saved - thread is discarded after response
response = await client.complete_chat("Hello!")

# No thread ID saved - thread is discarded after response
response = await client.complete_chat("Hello!")

Persistent Threads (for conversations):

# Thread is created and maintained
conversation = client.create_conversation()
await conversation.send("First message")
await conversation.send("Second message")

# Resume later
resumed = client.resume_conversation(conversation.thread_id)

# Thread is created and maintained
conversation = client.create_conversation()
await conversation.send("First message")
await conversation.send("Second message")

# Resume later
resumed = client.resume_conversation(conversation.thread_id)

Automatic vs Manual Thread Management¶

The SDK offers two approaches:

# SDK manages thread lifecycle
conversation = client.create_conversation()
response = await conversation.send("Hello")

# SDK manages thread lifecycle
conversation = client.create_conversation()
response = await conversation.send("Hello")

# You manage threads directly
thread = await client.create_thread()
run = await client.create_run(
    thread_id=thread.id,
    agent_id="my-agent"
)
run = await client.wait_for_run(thread.id, run.id)
messages = await client.get_thread_messages(thread.id)

# You manage threads directly
thread = await client.create_thread()
run = await client.create_run(
    thread_id=thread.id,
    agent_id="my-agent"
)
run = await client.wait_for_run(thread.id, run.id)
messages = await client.get_thread_messages(thread.id)

Use manual mode when:

  • Building custom conversation flows
  • Implementing complex multi-agent orchestration
  • Need fine-grained control over run lifecycle

Thread Metadata¶

Attach custom data to threads for filtering and organization:

conversation = client.create_conversation(metadata={
    "user_id": "user_123",
    "session_type": "support",
    "priority": "high"
})

conversation = client.create_conversation(metadata={
    "user_id": "user_123",
    "session_type": "support",
    "priority": "high"
})

const conversation = client.createConversation({
    metadata: {
        userId: "user_123",
        sessionType: "support",
        priority: "high"
    }
});

const conversation = client.createConversation({
    metadata: {
        userId: "user_123",
        sessionType: "support",
        priority: "high"
    }
});

var conversation = client.CreateConversation(new ConversationOptions
{
    Metadata = new Dictionary<string, string>
    {
        ["user_id"] = "user_123",
        ["session_type"] = "support",
        ["priority"] = "high"
    }
});

Relationship Diagram¶

┌─────────────────────────────────────────┐
│              Thread                      │
│  thread_id: "thread_abc123"             │
│  participants: [user, agent]            │
│  metadata: { ... }                      │
└─────────────────────────────────────────┘
               │
               ├── Message 1 (user)
               ├── Message 2 (agent)
               │
               ├── Run 1 ─────┐
               │               ├── Message 3 (agent)
               │               └── Message 4 (function_call)
               │
               └── Run 2 ─────┐
                               ├── Message 5 (function_result)
                               └── Message 6 (agent)

┌─────────────────────────────────────────┐
│              Thread                      │
│  thread_id: "thread_abc123"             │
│  participants: [user, agent]            │
│  metadata: { ... }                      │
└─────────────────────────────────────────┘
               │
               ├── Message 1 (user)
               ├── Message 2 (agent)
               │
               ├── Run 1 ─────┐
               │               ├── Message 3 (agent)
               │               └── Message 4 (function_call)
               │
               └── Run 2 ─────┐
                               ├── Message 5 (function_result)
                               └── Message 6 (agent)
  • A thread contains many messages and runs
  • Each run belongs to one thread
  • Messages are appended in chronological order
  • Runs can span multiple messages (especially with tool calls)
